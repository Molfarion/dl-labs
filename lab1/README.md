# ЛР1. Реалізація та перевірка зворотного поширення похибки

Мережа `X → Linear(4, 8) → ReLU → Linear(8, 3)`, крос-ентропія, усереднена за об'єктами.
Усі обчислення у float64. Дані — Iris, стратифікований поділ 35/15 на клас, стандартизація за статистиками навчальної вибірки (`ddof=0`).

## Відтворення

```bash
uv sync
cd lab1
uv run python checks.py         # правильна реалізація: звірка з PyTorch + чисельна перевірка
uv run python checks.py --bug   # дослід із навмисною помилкою (без ділення на N)
```

Файли:

- `lab1.py` — підготовка даних, ініціалізація, прямий і зворотний прохід у NumPy (без autograd).
- `checks.py` — еталонна мережа в PyTorch, звірка з нею, чисельна перевірка, прапорець `--bug`.

Помилку з пункту 4 відтворює параметр `backward_pass(..., divide_by_n=False)`; за замовчуванням `divide_by_n=True`, тобто правильна реалізація.

## Прямий прохід

Позначення: $N = 105$ — кількість об'єктів, $Y$ — one-hot матриця міток ($N \times 3$).

$$
\begin{aligned}
Z_1 &= X W_1 + b_1 && (N \times 8)\\
A_1 &= \mathrm{ReLU}(Z_1) = \max(Z_1, 0) && (N \times 8)\\
Z_2 &= A_1 W_2 + b_2 && (N \times 3) \text{ — логіти}\\
\log P_{ik} &= (Z_{2,ik} - m_i) - \log \sum_j e^{Z_{2,ij} - m_i},\quad m_i = \max_j Z_{2,ij} && (N \times 3)\\
L &= -\frac{1}{N}\sum_{i=1}^{N} \log P_{i, y_i} && \text{скаляр}
\end{aligned}
$$

Зсув на максимум $m_i$ не змінює softmax, але гарантує, що найбільша експонента дорівнює $e^0 = 1$: немає переповнення, а сума під логарифмом $\ge 1$, тож логарифм завжди скінченний.

## Зворотний прохід

$$
\begin{aligned}
\frac{\partial L}{\partial Z_2} &= \frac{1}{N}(P - Y) && (N \times 3)\\
\frac{\partial L}{\partial W_2} &= A_1^\top \frac{\partial L}{\partial Z_2} && (8 \times 3)\\
\frac{\partial L}{\partial b_2} &= \sum_{i} \left(\frac{\partial L}{\partial Z_2}\right)_{i,:} && (3)\\
\frac{\partial L}{\partial A_1} &= \frac{\partial L}{\partial Z_2} W_2^\top && (N \times 8)\\
\frac{\partial L}{\partial Z_1} &= \frac{\partial L}{\partial A_1} \odot [Z_1 > 0] && (N \times 8)\\
\frac{\partial L}{\partial W_1} &= X^\top \frac{\partial L}{\partial Z_1} && (4 \times 8)\\
\frac{\partial L}{\partial b_1} &= \sum_{i} \left(\frac{\partial L}{\partial Z_1}\right)_{i,:} && (8)
\end{aligned}
$$

Звідки береться перша формула: для одного об'єкта $\ell = -\log P_{y}$, $P = \mathrm{softmax}(z)$, і $\partial \ell / \partial z_k = P_k - [k = y]$. Оскільки $L$ — середнє за $N$ об'єктами, кожен рядок ділиться на $N$. Градієнт за зміщенням — сума за об'єктами, бо $b$ додається до кожного рядка (broadcast). Похідна ReLU — індикатор $[Z_1 > 0]$ (у точці 0 беремо 0, як і PyTorch).

Розмірності кожного градієнта збігаються з розмірністю відповідного параметра: $W_1: 4\times8$, $b_1: 8$, $W_2: 8\times3$, $b_2: 3$.

### Збережені проміжні значення (`cache`)

| Значення | Розмірність | Навіщо потрібне |
|---|---|---|
| `X` | $N \times 4$ | для $\partial L/\partial W_1 = X^\top \cdot \partial L/\partial Z_1$ |
| `z1` | $N \times 8$ | маска похідної ReLU $[Z_1 > 0]$ |
| `a1` | $N \times 8$ | для $\partial L/\partial W_2 = A_1^\top \cdot \partial L/\partial Z_2$ |
| `probs` ($P$) | $N \times 3$ | для $\partial L/\partial Z_2 = (P - Y)/N$ |
| `y` | $N$ | щоб відняти 1 у стовпці правильного класу |

$W_2$ береться з `params` (потрібна для $\partial L/\partial A_1$). Логіти $Z_2$ не зберігаються: після обчислення $P$ вони для градієнтів не потрібні.

## Звірка з PyTorch

Еталон: `nn.Sequential(nn.Linear(4, 8), nn.ReLU(), nn.Linear(8, 3)).double()` та `nn.functional.cross_entropy` (усереднення за замовчуванням). `nn.Linear` зберігає вагу як `(out, in)`, тому в неї копіюється `W.T`, а отриманий градієнт транспонується назад.

Втрата NumPy: `1.4562007801142816`
Втрата PyTorch: `1.4562007801142818`

Критерій: $|a - b| \le 10^{-12}$ для кожного елемента, усі значення скінченні.

| Величина | Максимальна абсолютна різниця NumPy / PyTorch | Перевірку пройдено |
|---|---|---|
| Втрата | 2.220e-16 | так |
| Градієнт W1 | 5.551e-17 | так |
| Градієнт b1 | 2.949e-17 | так |
| Градієнт W2 | 8.327e-17 | так |
| Градієнт b2 | 1.388e-16 | так |

Різниці порядку машинного епсилону float64 ($\approx 2.2 \cdot 10^{-16}$) — це лише інший порядок округлень.

## Чисельна перевірка

Центральна різниця $g_\text{num} = \dfrac{L(\theta + \varepsilon) - L(\theta - \varepsilon)}{2\varepsilon}$, $\varepsilon = 10^{-6}$; параметр змінюється на місці й після цього відновлюється. Критерій: $|g_\text{num} - g_\text{manual}| \le 10^{-7}$.

| Параметр | Градієнт backward() | Чисельна похідна | Абсолютна різниця | Перевірку пройдено |
|---|---|---|---|---|
| W1[0, 0] | -0.019920184331 | -0.019920184391 | 6.034e-11 | так |
| b1[0] | -0.070566111584 | -0.070566111621 | 3.633e-11 | так |
| W2[0, 0] | 0.135230208605 | 0.135230208698 | 9.218e-11 | так |
| b2[0] | 0.085521644842 | 0.085521644988 | 1.460e-10 | так |

Різниця $\sim 10^{-10}$ очікувана: похибка центральної різниці $O(\varepsilon^2)$ плюс похибка округлення $\sim \epsilon_\text{mach} \cdot |L| / \varepsilon \approx 10^{-10}$.

## Дослід із навмисною помилкою

Зміна: у $\partial L / \partial Z_2$ прибрано ділення на $N$ (`divide_by_n=False`). Функція втрат, еталон PyTorch і формула чисельної похідної не змінювались; параметри початкові, 105 об'єктів, без оновлень ваг.

### Прогноз (записаний до запуску)

- **Втрата не зміниться** — прямий прохід не змінено, помилка лише у backward.
- **Усі ненульові градієнти збільшаться рівно в $N = 105$ разів.** Множник $1/N$ з'являється лише в $\partial L/\partial Z_2$, а всі наступні кроки (множення на $A_1^\top$, $W_2^\top$, маска ReLU, $X^\top$, суми) лінійні, тому множник $N$ переноситься до всіх чотирьох градієнтів. Нульові елементи залишаться нульовими. Напрямок градієнта не зміниться — лише масштаб.
- **Виявити помилку мають** звірка з PyTorch (усі чотири градієнти, але не втрата) та чисельна перевірка (усі чотири параметри), бо обидві порівнюють з правильною похідною функції втрат.

### Результат (`uv run python checks.py --bug`)

Наприклад, $-2.091619354708 / -0.019920184331 = 105.0$. Відношення «з помилкою / правильний» дорівнює 105 для кожного елемента всіх чотирьох градієнтів (нульових елементів на початкових вагах немає).

### Зіставлення з прогнозом

Прогноз підтвердився повністю: втрата збігається з PyTorch, усі градієнти масштабовано рівно в $N$ разів, обидві перевірки градієнтів помилку виявили. Висновок: перевірка лише значення втрати не виявляє помилок у backward — потрібно порівнювати самі градієнти. Така помилка небезпечна тим, що навчання з нею все одно може працювати (градієнт має правильний напрямок), але фактичний крок навчання стає в $N$ разів більшим і залежить від розміру батча.

## Висновки

- Ручний backprop збігається з PyTorch autograd до $\sim 10^{-16}$, тобто до округлення float64, і з чисельною похідною до $\sim 10^{-10}$.
- Для зворотного проходу достатньо зберегти $X$, $Z_1$, $A_1$, $P$, $y$ (та мати $W_2$).
- Стабільна log-softmax зі зсувом на максимум дає скінченну втрату за будь-яких логітів.
- Дві незалежні перевірки (autograd та чисельна похідна) надійно виявляють помилку масштабу градієнта, яку не видно за значенням втрати.
